# Design Handoff

**개발자가 그대로 구현할 수 있는 수준으로 정리한 UI 설계 문서 모음.**

디자인 시안만 던지면 구현 단계에서 질문이 쏟아집니다.
이 값은 몇 px인지, 이 상태일 땐 어떻게 보이는지, 데이터가 없으면 뭘 띄우는지.
그래서 **시안과 함께 토큰·상태·정책·예외를 같이 넘기는 문서**를 만들어 왔습니다.

🔗 **[화면 미리보기 (GitHub Pages)](https://chein206.github.io/design-handoff/)** — 실제로 클릭해 볼 수 있는 hifi 프로토타입

## 담고 있는 것

| 항목 | 내용 |
|---|---|
| **Design Tokens** | 색상(역할별 HEX) · 타이포(weight·크기 위계) · radius · spacing · shadow · 아이콘 규칙 |
| **Global Layout** | 셸 구조를 px 단위로. 사이드바 폭, 활성 상태 표현, 상단바 높이 |
| **Screens / Views** | 화면별 Purpose · Layout · Components |
| **Interactions** | hover · focus · 토글 · 라우팅 동작 |
| **State Management** | 상태 변수 전체와 파생값 |
| **예외 케이스** | 빈 값 표기, 비활성 행 처리, 조건부 노출 |
| **계산 로직** | 화면에 계산이 있는 경우 공식을 그대로 (금융 계산 등) |

## 어떻게 만들었나

**[Claude Design](https://claude.com/product/design)** (Anthropic Labs, 2026.04 출시)으로 작업하고,
**Handoff Bundle**로 정리해 **Claude Code로 구현**까지 이어갔습니다.

```
Claude Design          기존 코드베이스를 읽어 디자인 시스템 추출 → 화면 설계
      ↓ Handoff Bundle (이 저장소)
Claude Code            대상 스택으로 재구현
      ↓
실서비스 반영           app.scpadlab.com
```

출시 직후에 붙잡아 실무에 적용한 도구라, 정립된 방법론이 없는 상태에서
**"무엇을 문서에 담아야 개발이 막히지 않는가"** 를 직접 정하며 만들었습니다.
그 판단이 아래 항목 구성으로 남아 있습니다.

Figma로 산출물을 낸 경험은 많지 않습니다.
다만 담아야 할 내용 — 토큰 · 레이아웃 규격 · 상태값 · 예외 케이스 · 로직 — 은
도구가 바뀌어도 같다고 생각합니다.

## 이 문서들에 대해

`.dc.html` 파일은 **HTML로 만든 디자인 레퍼런스**입니다.
의도한 룩앤필과 동작을 보여주는 프로토타입이며, 그대로 배포하는 프로덕션 코드가 아닙니다.
구현 시에는 대상 코드베이스의 프레임워크와 관례로 재구현하는 것을 전제로 합니다.

브라우저에서 직접 열려면 같은 폴더의 `support.js`가 필요합니다(프로토타입 런타임).

> **개인정보 처리** — 이 저장소의 목업에 보이는 고객명·연락처·이메일·사업자정보는
> 전부 **가상의 값으로 교체**했습니다. 원본 작업본에는 실제 운영 데이터가 들어 있었고,
> 공개 시점에 전수 치환했습니다. 레이아웃·토큰·상태·로직 검토에는 영향이 없습니다.
